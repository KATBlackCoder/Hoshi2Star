## P3 — IPC (`perf/fe-p3-ipc`, empilée sur P2)

### Vérifications préalables dans le code

- `h2s://project/resynced` n'est émis que quand la resynchronisation est appliquée (`commands/resync.rs:94`) ;
  `h2s://project/import-done` à la fin de `apply_h2s_import` (`commands/pack.rs:560`). `set_text_categories`
  (couverture) n'émet rien : son appel direct à `refreshProjectData` reste.
- **I3, point de l'audit à nuancer.** `segments-updated` ne transporte que `target_text` et `status`
  (`llm/progress.rs`). Le pipeline écrit aussi `qa_score` et répare d'autres lignes du même nom
  (`persist_batch_results`, `llm/pipeline.rs:160-226`) ; ces changements n'arrivent par aucun événement. Une
  resynchronisation après `completed` reste donc nécessaire quand le run a écrit quelque chose. Elle se fait
  désormais **sans démonter la liste** (pas d'écran « Chargement », position conservée), et elle est sautée quand
  le run n'a rien écrit (`translated + needsReview + repaired = 0`). Une resynchronisation plus fine
  (`qa_score` dans l'événement) demanderait un changement Rust : hors périmètre.
- **I5, décision.** Les stats par projet de la Bibliothèque passent sous React Query (seule vue qui les montre) ;
  les fichiers restent dans le store (lus par `FileTree`, écrits par `openProject`, `deleteProject`), avec un
  seul rafraîchissement par événement, centralisé. Tout passer sous React Query n'aurait pas simplifié.

### Ce qui a été fait

- **I1** `activeProjectStats`, `setActiveProjectStats` et `useActiveProjectStats` supprimés. `get_project_stats`
  n'est plus appelé à l'ouverture que pour le toast d'extraction (pas pour un projet restauré).
- **I2** Nouveau hook `useProjectDataSync` (monté dans `App`) : seul endroit qui réagit à `llm/completed` (si le
  run a écrit), `import-done` et `resynced` ; il recharge les fichiers une fois et invalide les vues en cache.
  Appels en double supprimés dans `resync.ts`, `PackImportWizard`, `SegmentGrid` (`reloadSourceFiles`,
  `reloadProjectStats`) et `GlobalSearchResults` (qui ne relance plus la recherche après un run sans écriture).
- **I3** voir ci-dessus (`loadSegments(…, inPlace)`, `runWroteSegments` dans `stores/llm.ts`).
- **I4/I5** `ProjectList` : une seule requête pour toutes les stats (`allSettled`, un seul résultat), mise en
  cache jusqu'à une écriture. `loadAllProjects` ne remplace plus la liste si aucun projet n'est nouveau (c'était
  la cause du double chargement des stats à chaque montage).
- **I6** `invalidateSegmentViews()` (`lib/queryClient.ts`) marque périmés `project-stats`, `qa-report` et
  `tm-suggestions` après chaque écriture (sauvegarde d'un segment, run, import, resync, couverture, ouverture).
  `activeSegmentId` ajouté à la clé `qa-check`. Le `QueryClient` de l'app vient de `lib/queryClient.ts` (il était
  créé dans `main.tsx`, mêmes options).
- **I7** `loadSettings` lance ses 12 lectures en parallèle (même repli sur les anciennes clés Ollama, testé).
