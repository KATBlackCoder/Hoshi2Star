## P3 — IPC (`perf/fe-p3-ipc`, empilée sur P2)

### Vérifications préalables dans le code

- `h2s://project/resynced` n'est émis que quand la resynchronisation est appliquée (`commands/resync.rs:94`) ;
  `h2s://project/import-done` à la fin de `apply_h2s_import` (`commands/pack.rs:560`). `set_text_categories`
  (couverture) n'émet rien : son appel direct à `refreshProjectData` reste.
- **I3, point de l'audit à nuancer.** `segments-updated` ne transporte que `target_text` et `status`
  (`llm/progress.rs`). Le pipeline écrit aussi `qa_score` et répare d'autres lignes du même nom
  (`persist_batch_results`, `llm/pipeline.rs:160-226`) ; ces changements n'arrivent par aucun événement. Une
  resynchronisation après `completed` reste donc nécessaire quand le run a écrit quelque chose. Elle se fait
  désormais **sans démonter la liste** (pas d'écran « Chargement », position conservée), et elle est sautée quand
  le run n'a rien écrit (`translated + needsReview + repaired = 0`). Une resynchronisation plus fine
  (`qa_score` dans l'événement) demanderait un changement Rust : hors périmètre.
- **I5, décision.** Les stats par projet de la Bibliothèque passent sous React Query (seule vue qui les montre) ;
  les fichiers restent dans le store (lus par `FileTree`, écrits par `openProject`, `deleteProject`), avec un
  seul rafraîchissement par événement, centralisé. Tout passer sous React Query n'aurait pas simplifié.
